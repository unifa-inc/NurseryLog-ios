## このアプリについて

NurseryLog は、保育施設向けの日次活動管理アプリです。保育士は、園児が一日の中で行った活動（食事・午睡・排泄など）をこのアプリで記録し、あとから振り返ることができます。

> 📝 **本アプリについての注記**
>
> - 本アプリは、採用課題のために作成したコードです。
> - 当社（ユニファ）の社内コードとは直接の関連はありません。
> - 一般的な保育業務の一部を単純化したものです。

### 想定ユーザー

保育園・保育施設で働く保育士。日中の忙しい業務の合間に、手早く記録を残せることが求められます。

### 主な画面とフロー

1. **タイムライン画面**
   選択した日付に登録されているアクティビティが一覧表示されます。日付を切り替えることで、過去の記録を振り返ることができます。
2. **アクティビティ追加画面**
   タイムラインから「＋」をタップして開きます。タイトル・メモなどを入力して保存すると、タイムラインに反映されます。
3. **アクティビティ詳細画面**
   タイムライン上の各アクティビティをタップすると、詳細情報が表示されます。

この一連の「記録する → 一覧で振り返る → 詳細を確認する」という流れが、アプリの中心的な体験です。

## セットアップ

1. リポジトリをクローンする
2. `pod install` を実行する
3. `NurseryLog.xcworkspace` を開く
4. ビルド・実行する

## API Key Configuration（Task 2用）

`NurseryLog/Config/ExampleConfig.xcconfig` をコピーして `Local.xcconfig`（gitignore対象）を作成し、APIキーを設定してください。

```
// NurseryLog/Config/Local.xcconfig
GEMINI_API_KEY = your_key_here
```

`Info.plist` から参照します。

```xml
<key>GEMINI_API_KEY</key>
<string>$(GEMINI_API_KEY)</string>
```

コードから読み込みます。

```swift
Bundle.main.infoDictionary?["GEMINI_API_KEY"] as? String ?? ""
```

`NurseryLog/Services/` フォルダに、Task 2で実装するAPI通信用のServiceクラスを追加してください（現在は空フォルダです）。

## データ仕様

アプリケーションは、ローカルJSONファイルからデータを読み込み、新規登録データは内部データベースへ保存します。

事前に10件以上のサンプルデータが投入されています。

### Activity データ構造

| 項目 | 型 | 備考 |
| --- | --- | --- |
| id | String (UUID) | 自動生成 |
| date | String | ISO 8601形式: yyyy-MM-dd |
| time | String | 24時間形式: HH:mm |
| category | String (enum) | MEAL, NAP, OUTDOOR, INDOOR, OTHER |
| title | String | 必須 |
| notes | String? | 任意 |
| createdAt | String | ISO 8601 timestamp |

## Task 1 — 不具合修正

### 実施内容

スタータープロジェクトには、意図的に不具合が含まれています。

すべての不具合を調査・修正し、内容を `BUG_FIXES.md` に記載してください。

> ⚠️ **候補者にはセットA・B・Cのいずれか1セットのみが割り当てられます。**
> 担当セットは別途ご案内します。指定されたセットのみをご確認ください。
>
> - [セットA](./.doc/BUG_SET_A.md)
> - [セットB](./.doc/BUG_SET_B.md)
> - [セットC](./.doc/BUG_SET_C.md)

### 各不具合対応における要件

**根本原因を特定すること**
表面的な症状ではなく、発生原因まで分析してください。

**適切な責務レイヤーで修正すること**
本来責務を持つレイヤーで対応してください。

例：

- ViewModelへ不要なRepository責務を追加しない
- ViewへBusiness Logicを実装しない

**Conventional Commits形式でコミットすること**

### コミットメッセージ形式

```
fix(scope): short description of what was fixed
```

例：

```
fix(timeline): sort activities by time after loading from repository
```

```
fix(add-activity): use Locale.US in date formatter to match ISO 8601 schema
```

```
fix(timeline): check filtered list size for empty state, not total list
```

### BUG_FIXES.md 記載内容

各不具合について、以下を記載してください。

1. 不具合内容（症状）
2. 根本原因
3. 実施した修正内容
4. 修正方針および理由

### 取り組み方について

本課題は、実際の本番運用における不具合対応を想定しています。

以下を意識して進めてください。

- コードを正確に読む
- データフローを把握する
- 原因を理解したうえで修正する
- 必要最小限かつ適切な修正を行う

なお、不具合修正に関連しない大規模なリファクタリングは不要です。

## Task 2 — 新機能開発

### 課題内容

保育士の業務を効率化する機能を提案・実装してください。

目安として、1日あたり10分〜数時間程度の時間削減を意識してください（あくまで目安であり、厳密な証明を求めるものではありません）。

条件：

- 完全無料で利用可能な外部APIを利用すること
- クレジットカード登録不要
- 有料プラン契約不要

### API例（参考）

| API | 内容 |
| --- | --- |
| Google Gemini API | AI文章生成（無料枠あり） |
| LibreTranslate / MyMemory | 翻訳API |
| VoiceRSS / ResponsiveVoice | 音声読み上げAPI |
| Pexels API | フリー画像取得API |
| Unsplash API | フリー画像取得API |
| Nager.Date API | 祝日情報取得API |
| DiceBear Avatars API | アバター生成API |

※ 上記以外のAPI選定も可能です。

重要なのは、以下を説明できることです。

- なぜそのAPIを選定したのか
- 本課題およびデモ用途において十分な無料利用範囲であること

### 技術要件（全7項目必須）

1. **無料APIを使用すること** — クレジットカード登録や有料契約が不要であること
2. **MVVMアーキテクチャを維持すること** — 既存のViewModel / Repository構成を変更・破壊しないこと
3. **Serviceレイヤーを追加すること** — API通信処理は専用Serviceクラスへ実装してください
4. **Loading状態を実装すること** — API通信中にローディング表示を行ってください（例：Spinner、Skeleton UI）
5. **Error状態を実装すること** — 通信失敗時にはエラーメッセージ表示とRetry操作を提供してください
6. **APIキーをハードコードしないこと**
   - Android: `local.properties + BuildConfig`
   - iOS: `.xcconfig + Info.plist`
   を使用してください。
7. **結果を編集可能にすること** — 生成・取得した内容は、保存前にユーザーが編集できるようにしてください。

### FEATURE.md 記載内容

以下4項目へ回答してください。

**Time Saving**
どの業務において、どのように業務効率化につながるのか。保育士の実際の業務フローを踏まえて説明してください（削減時間の目安があれば併せて記載してください）。

**API Choice**
なぜそのAPIを選定したのか。他APIと比較したうえでの選定理由を説明してください。

**Architecture**
なぜその設計・構成を採用したのか。検討した代替案があれば併せて記載してください。

**Trade-offs**
意図的に実装対象外とした内容は何か。今後拡張する場合に追加したい内容も記載してください。

## AIツール利用ポリシー

ChatGPT、Claude、Copilot、Cursor等のAIツール利用は許可しています。

弊社チームでも日常的に活用しております。

本課題において評価対象となるのは、

- AIを使用したかどうか

ではなく、

- AIをどのように活用したか

です。

### 適切なAI活用例

- 明確な目的を持ったプロンプト設計
- 出力内容を批判的に確認する
- 既存アーキテクチャへ適合させる
- 不適切な提案を採用しない
- 実装内容を自身で説明できる

### 不適切なAI活用例

- 課題全文を入力し、そのまま提出する
- 既存設計と整合性が取れていない
- 実装内容を説明できない

### AI_USAGE.md 記載内容

AI利用内容について、以下を記録してください。

1. 使用したAIツール名
2. 実際に入力したプロンプト（原文）
3. 影響したコードまたはドキュメント
4. 採用・修正・却下した内容とその理由（2〜3文程度）
